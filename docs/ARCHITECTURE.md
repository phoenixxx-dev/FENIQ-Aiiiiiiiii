# البنية

## الطبقات والاتجاه

```
المتصفح (Next.js)
      │  HTTP + أنواع مولَّدة من OpenAPI
      ▼
apps/api  (FastAPI)  ── ينسّق، لا يحسب ──┐
      │                                  │
      │ ARQ (Redis)                      │ يقرأ/يكتب
      ▼                                  ▼
apps/api/workers ──► packages/data-engine   Postgres (ميتاداتا فقط)
                            │
                            ▼
                    التخزين: raw/ + processed/ (Parquet)
```

**الاتجاه أحادي:** الواجهة تعرف الـAPI، والـAPI يعرف المحرك، والمحرك لا
يعرف أحداً. أي استيراد معاكس خرق للقاعدة الذهبية #4.

## من أين يأتي كل شيء

| الشيء | مصدره الوحيد |
|---|---|
| الأرقام | `data-engine` (مع `Evidence`) |
| نوع الرسم | `phoenix/charts.py` — الواجهة تترجم `ChartSpec` ولا تقرّر |
| معاني الأعمدة | `phoenix/semantic.py` + `dictionaries/ar.yaml` |
| قائمة المفاهيم في الواجهة | `GET /datasets/concepts` ← القاموس نفسه |
| أنواع TypeScript | `./scripts_gen_types.sh` ← OpenAPI ← نماذج Pydantic |
| النصوص العربية | `apps/web/src/i18n/ar.json` |
| رسائل الخطأ للمستخدم | الخادم (`message_ar`) — هو من يعرف السبب |

## مسار الملف من الرفع إلى الجواب

1. `POST /datasets/upload-url` — يحجز سجلاً ويُرجع رابط PUT موقّعاً.
2. المتصفح يرفع **مباشرة إلى التخزين** (مع S3؛ محلياً عبر تذكرة موقّعة).
3. `POST /datasets/{id}/complete` — يتحقق من وصول الكائن ويُنشئ Job.
4. العامل: تحقق ← قراءة ← توصيف ← دلالة ← تنظيف ← تحليل ← اكتشافات.
5. التقدّم يصل للواجهة ببث SSE؛ كل مرحلة باسمها العربي.
6. اللوحة والأسئلة تقرأ Parquet من نسخة محلية مخزَّنة مؤقتاً.

## القرارات التي تُعيد الحساب

تصحيح معنى عمود (`PATCH /schema`) ورفض عملية تنظيف (`PATCH /cleaning`)
لا يعدّلان المخرجات المحفوظة، بل **يعيدان تشغيل خط الأنابيب من الملف
الأصلي** بالقرار مطبَّقاً — لأن كل ما بعد الدلالة يعتمد عليها. القرارات
محفوظة على `datasets` وتُعاد مع كل معالجة لاحقة.

## ما لا يعرفه المحرك

المستخدمين، الجلسات، التخزين السحابي. يُشغَّل من سطر الأوامر أو نوتبوك أو
اختبار بلا أي خدمة تعمل — وهذا ما يجعل اختباره سريعاً وصادقاً.

**الاستثناء الوحيد وهو مُعلَن:** نداء نموذج اللغة. كل الشبكة داخل المحرك
محصورة في `phoenix/llm_provider.py`، وكل مستهلك يقبل `call_fn` محقوناً —
فالاختبارات لا تلمس شبكة إطلاقاً، وتبديل المزوّد تعديل ملف واحد. حارسٌ يفشل
عند أول استيراد لعميل شبكة في أي وحدة أخرى (ق-36).
